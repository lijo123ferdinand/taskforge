# Observability Basics

Observability is the ability to explain a system's behaviour from the outside using logs, metrics and traces. Metrics answer whether something is wrong, while traces answer where.

Structured logs with request identifiers let engineers follow a single request across services. Sampling keeps tracing affordable at high request volumes.

Service level objectives turn raw telemetry into decisions. An error budget tells a team when to slow feature work and invest in reliability.
